# Development findings

- The imported repo contained only `requirements 2.txt`, not application code. `app/` is a minimal FastAPI wrapper created to serve TransKun on port 3000.
- Run `docker compose -f docker-compose.base44.yml up -d`. The plain Python runtime bind-mounts this checkout; Uvicorn reloads Python edits. HTML is read on every request, so refresh the preview after HTML edits.
- First startup installs ffmpeg/sox and Python dependencies, including the 50 MB TransKun package with its bundled checkpoint. The named virtualenv and pip-cache volumes speed subsequent startups. CPU-only PyTorch and NumPy 1.x are intentional; setuptools is pinned for legacy dependencies.
- `requirements.base44.lock.txt` constrains all installed dependencies. When changing dependencies, regenerate the constraints from the tested container with `docker compose -f docker-compose.base44.yml exec -T web /opt/venv/bin/pip freeze` and rerun startup. Quote `requirements 2.txt` in pip includes because its filename contains a space.
- Startup loads the bundled TransKun 2.0.1 checkpoint on CPU before accepting requests. `/health` reports ready only after load; it is the Compose healthcheck. No external credentials are required. Startup also compiles the model's processFramesBatch with torch.compile (max-autotune) and runs a warmup pass, so the first real request is fast. g++ is installed for inductor C++ codegen; TORCHDYNAMO_CAPTURE_SCALAR_OUTPUTS=1 avoids graph breaks. Gradient checkpointing is disabled for inference.
- Verify `curl -fsS http://localhost:3000/health` and `curl -F 'file=@/tmp/piano.wav' http://localhost:3000/transcribe -o /tmp/result.mid`; successful MIDI starts with `MThd`. Synthetic 1-second audio was tested successfully. Do not infer transcription accuracy from that synthetic test.
- The demo accepts at most 200 MB and 40 minutes per audio, with one inference at a time. Uploads use temporary disk files deleted on completion; there is no durable file storage. API is unauthenticated, intended for development only. Add authentication and production hosting before wider use.
- The user-facing frontend is a separate Vercel app (`https://tetomidi-transcriber.vercel.app`) that is NOT in this repository — only the FastAPI backend is here. The frontend calls this API cross-origin, so CORS matters: the app uses `allow_origins=['*']`, which makes the browser preflight (`OPTIONS`) for `/transcribe` and `/transcribe-url` succeed from the Vercel origin.
- Verified backend-side connection: preflight returns 200 with `access-control-allow-origin: *`, and a real `POST /transcribe` sent with `Origin: https://tetomidi-transcriber.vercel.app` through the public link returned a valid MIDI (`MThd`). No backend change was required — to connect, point the Vercel app's API base URL at `https://3000-$BASE44_PUBLIC_HOST_SUFFIX`.
- `BASE44_PUBLIC_HOST_SUFFIX` is still passed into the service but the home page no longer renders a copyable service link (that UI was removed). The public entry point is `https://3000-$BASE44_PUBLIC_HOST_SUFFIX`; it is a development preview and not reliable 24/7 hosting, so the external frontend's hardcoded backend URL must be updated whenever the sandbox is recreated.
